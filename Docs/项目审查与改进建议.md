# 《渡口灯火》项目审查与改进建议

审查时间：2026-11-25
审查范围：Assets/scrpits 全部脚本、4 个构建场景、ItemSO 与场景配置
编译状态：无报错（Editor.log 无 `error CS`）

---

## 一、结论摘要

功能量已经够撑起一个可玩切片，但**"完成度"卡在三个地方**：

1. **世界进度不落盘** —— 玩家离开场景，修好的桥会断、交过的委托会重置，而背包里的奖励不回滚，等于可以重复刷。
2. **有一个场景玩家永远进不去** —— Willowreach 在构建列表里，但没有任何入口。
3. **没有存档** —— 这是评审判断"这是作品还是作业"的第一道分界线。

以下问题按优先级排列，建议按顺序处理。

## 二、BUG 清单

### P0-1 世界进度不保存 + 可重复领奖

**位置**：`RPG2Adventure.cs`
**字段**：`accepted[4]`、`collected`、`SuppliesDelivered`、`BridgeRepaired`、`BeaconCount`、`TileClaimed`、`TreasureClaimed`

全部是运行时字段，`PlayerPrefs` 里只有钓鱼点和日志。场景切换后：

- 桥回到断裂状态、信标全灭、委托回到未接
- 但**背包与奖励保留** —— 同一份委托可以反复交付，金币和材料无限增长

**修法**：见第四节存档方案。最低限度要把这 7 个字段写进存档，并在读档时还原。

---

### P0-2 Willowreach 没有入口

**证据**：
- `RPG1.unity` → `sceneToLoad: RPG2` ✅
- `RPG2.unity` → `sceneToLoad: RPG1` ✅
- `Willowreach.unity` → 无 `SceneChanger` 组件 ❌

**修法**：在 RPG2 北岸桥头放一个 `SceneChanger`（目标 `Willowreach`），并在 Willowreach 放回程入口；或暂时从 Build Settings 移除，避免"看得见进不去"。

---

### P1-3 速度增益层数永久泄漏

**位置**：`Inventory&Shop/Useltem.cs`
**原因**：`static int speedStacks` 只在 `EffectTimer` 结束时 `--`。buff 生效期间切场景/退出，协程被销毁，层数不归还。

**后果**：累计 3 次中断后，`MaxSpeedStacks` 永久占满，吃南瓜再也不加速，只能重启游戏。

**修法**（二选一）：
- 改成实例化 buff 列表，并在 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 时清零（推荐）
- 或给 `speedStacks` 加一个"按时间衰减"的兜底

---

### P1-4 钓鱼时切场景，角色动画可能停住

**位置**：`FishingRig2D.WearPose()` / `End()`
**原因**：抛竿时 `animator.enabled = false`，只靠 `End()` 恢复。若玩家是常驻对象（`PersistentPrefabs/Player`），钓鱼中切场景 → rig 随场景销毁、`End()` 不再被调用 → `Animator` 永久 disabled。

**修法**：在 `FishingRig2D.OnDisable()` / `OnDestroy()` 里调用 `RestorePose()`；并在 `RPG2Adventure.OnDisable()` 里调 `FishingRig2D.End()`。

---

### P1-5 修桥后任务文本自相矛盾

**位置**：`RPG2Adventure.QuestProgress(1)`
**现象**：修桥消耗 3 捆木料后 `Timber == 0`，任务页显示「收集木料 0 / 3」+「渡桥已修复」。

**修法**：`BridgeRepaired` 为真时直接显示「木料已交付 · 渡桥已修复」，不再读数量。

## 三、流程完整性

| 环节 | 状态 | 说明 |
|---|---|---|
| 登录 → RPG1 | ✅ | 依赖本机 `127.0.0.1:18765` 账号服务 |
| RPG1 ↔ RPG2 | ✅ | 双向 SceneChanger |
| RPG2 → Willowreach | ❌ | 无入口 |
| 存档 / 读档 | ❌ | 完全没有 |
| 回主菜单 / 登出 | ⚠️ | 代码里有 `LoadScene("Login")`，游戏内无入口 |
| 死亡处理 | ⚠️ | RPG1、RPG2 各一套；RPG2 是回营火恢复一半血 |
| 章节边界 | ❌ | 无"本章结束"，玩家不知道玩到哪算完 |
| 打包发布 | ⚠️ | WebGL 需注意 PlayerPrefs 同步与 Resources 音频体积 |

**对外发布还有一个额外风险**：登录依赖本地 Python 服务，别人拿到包会停在"无法连接账号服务"。发布版必须加离线降级（服务不可达 → 本地游客登录）。

## 四、存档方案（建议先做这个）

### 数据结构

```csharp
[Serializable]
public class SaveData
{
    public int version = 1;
    public string account;

    // 世界进度
    public bool q0Accepted, q0Delivered;
    public bool q1Accepted, bridgeRepaired;
    public bool q2Accepted;
    public int beaconCount;
    public bool q3Accepted, treasureClaimed;
    public string collectedIds;      // 已采集点，逗号分隔

    // 玩家
    public float x, y;
    public int health, maxHealth;

    // 背包
    public List<SlotData> slots;     // itemName + quantity

    // 时间与统计
    public int dayIndex, fish, cook, quests;
    public float phaseSeconds;
    public string sceneName;
}
```

### 存点

- 进入场景后 1 秒（等待场景初始化完成）
- 营火休息 / 旅舍休息
- 每次交付委托、修桥、点亮信标后
- 退出游戏时（`OnApplicationQuit`）

### 实现要点

1. `SaveSystem` 单例，序列化成 JSON 写到 `Application.persistentDataPath/save_{account}.json`
2. 每个系统实现 `Capture()` / `Restore()`，由 `SaveSystem` 统一调度
3. `collectedIds` 用 `RPG2Point` 的 `GetInstanceID()` 或场景内自定义编号（推荐后者，ID 跨版本不稳定）
4. 读档必须先于 `Start()` 里的初始化（用 `Awake` + `Script Execution Order`）
