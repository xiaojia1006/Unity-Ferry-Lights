# 《柳湾物语》作品集方案

目标：把这个工程从"自己在做的游戏"变成"能拿出去给人看的东西"。
核心原则：**小而完整 > 大而半成品**。招聘方和玩家都只花 3 分钟，看的是"完成度"和"你想清楚了什么"，不是工程量。

---

## 一、先定位：一句话说清这是什么

三个版本，按场合换用：

- **简历版（20 字）**：独立开发的 2D 治愈系 RPG，含委托系统、动态昼夜与天气、分层环境音设计。
- **itch 版（40 字）**：一个雨天渡口小镇的短篇 RPG。接四份委托、修一座断桥、点亮三盏灯，然后在天黑前回到营火旁。
- **口述版（30 秒）**：我在做一个"没有战斗压力"的 RPG，重点不是打怪，是让玩家在一个小地方待着。所以我把力气花在昼夜变化、雨雪、脚步声和音乐的情绪分层上，而不是数值成长。

> 关键：**先给"情绪/体验"，再给"系统"**。没人先关心你用了什么设计模式。

## 三、缺口：按性价比排序补这 5 件

1. **3–5 分钟可玩切片**（最重要）
   现在玩家进游戏不知道要干嘛、也没有"结束"。需要一个明确的：
   开场 60 秒引导（走到告示牌 → R 接第一份委托）→ 完成 1 份委托 → 回营火交付 → **出现"本章结束"字幕** → 可以重开。
   成本：1 天。收益：作品集从"工程"变成"作品"。
2. **存档**（目前完全没有）
   面试官一定会问"数据怎么持久化"。哪怕只存 `金币 / 委托进度 / 玩家位置 / 时间相位` 四项，用 `PlayerPrefs + JsonUtility` 就够，30 行代码。
3. **玩家失败的演出**
   现在血量归零是直接瞬移回营地，没有任何反馈。做一个 0.8 秒淡出 + "你在营火旁醒来" 的转场，观感差别巨大。
4. **首次进入的操作说明**
   不用做教程关，一个半透明操作卡（E 互动 / B 背包 / R 委托 / Tab 地图）在开场显示 5 秒即可。
5. **打包发布**
   Windows zip 上传 itch.io；如果能出 WebGL 更好（注意：WebGL 不支持 `Resources` 里 55MB 的 mp3 一次性加载，需要改 `StreamingAssets` 或降低码率）。

## 四、四种载体，按优先级做

| 载体 | 作用 | 成本 | 优先级 |
|---|---|---|---|
| **可玩 Demo**（itch.io 页面 + Windows/WebGL 包） | 唯一的"硬证据" | 1–2 天 | P0 |
| **60 秒演示视频**（无声也行，必须有字幕） | 简历/社交传播，很多人只看这个 | 半天 | P0 |
| **图文 Case Study**（1 篇，800–1200 字 + 6–8 张图） | 讲"你怎么想"，面试深聊的抓手 | 半天 | P1 |
| **简历条目**（3 行，量化） | 过筛 | 30 分钟 | P0 |

### 60 秒视频分镜（直接照拍）

| 时间 | 镜头 | 说明 |
|---|---|---|
| 0–5s | 登录页（星空 + 月亮 + 星光闪烁） | 第一眼要"好看" |
| 5–15s | 白天渡口全景，走到告示牌按 R 接委托 | 展示 UI 与交互 |
| 15–25s | 采蘑菇/南瓜 → 交付营火 → 获得奖励 | 展示闭环 |
| 25–35s | 按 F7 切雨：雨声起来、踩水花、光线压暗 | **核心卖点，必须给特写** |
| 35–45s | 按 F9 切夜：三盏灯点亮、营火呼吸光 | 视觉高潮 |
| 45–55s | 修桥 → 过桥 → 地图 Tab | 展示系统广度 |
| 55–60s | 定格标题 + 一句 tagline | 收尾 |

### Case Study 结构（别写成流水账）

1. **一句话**：这是什么、给谁玩。
2. **一个具体问题**：例如"玩家在雨天听不出环境，场景显得假"。
3. **我怎么解**：拆成"昼夜相位 × 天气强度 × 地面材质"三个维度，音乐做闪避、雨声跟随强度、脚步分地面。
4. **结果**：贴 3 张对比图（晴/雨/夜）+ 一句"玩家反馈"或自测结论。
5. **反思**：哪一步走了弯路（例如一开始用素材库脚步声，后来发现和手绘美术冲突，改成处理过的 foley）。**反思比成果更值钱。**

## 五、简历怎么写（可直接抄改）

> **《柳湾物语》— 独立开发（Unity 2D / C#）**
> · 独立完成 5 场景 2D RPG 的玩法、UI 与音频系统：4 条主线委托、钓鱼、护送，含奖励防重复与满包保护。
> · 设计并实现昼夜（4 相位）× 天气（晴/雨/雪）联动的表现层：6 套 BGM 交叉淡入、雨声随强度变化、脚步按地面材质切换。
> · 建立自动化验证：31 项玩法检查 + 238 项交互反馈检查，覆盖碰撞、任务状态与 UI 文本。

三条足够，别写"使用了 MVC 架构、熟悉设计模式"这种没有证据的话。
